# Architecture

## Structure
- src/data.ts: typed resource/equipment/enemy/core/base templates and tuning constants.
- src/model.ts: plain TypeScript simulation: ships, inputs, weapons, shields/integrity, layouts, ore pickups/tractors, bases, AI integration and save state.
- src/world.ts: seeded RNG, world metadata, continuous belt/cluster fields, spawn validation, deterministic chunk generation, sparse modification/tombstone storage and surveyed ore markers.
- src/asteroidGeometry.ts: seeded 10–16 vertex radial polygons, inward deformation, point/edge/segment geometry.
- src/mining.ts: asteroid state hydration, impact points, finite material removal and geometry revision updates.
- src/effectEvents.ts: renderer-independent transient visual event contract; src/effects.ts owns the reusable fixed-budget particle pool.
- src/collisions.ts: circle contacts and circle-vs-carved-polygon contacts; no Phaser dependency.
- src/enemyAI.ts: polygon-aware visibility tests. Model owns detection, squad patrol/formation and combat state.
- src/persistence.ts: browser storage adapter. GameModel.toSave/fromSave use a versioned JSON schema, also exported/imported as files.
- src/main.ts: Phaser scene/input and UI coordination; src/outfitter.ts generates the three-panel outfitter and exact stat comparisons; src/hud.ts generates the flight HUD. src/visuals.ts provides primitive drawing helpers; src/map.ts draws the explored map; src/audio.ts provides gesture-unlocked synthesized weapon profiles, loops, bus volumes and rate/voice limits. src/effectsRender.ts draws lightweight beams, projectiles, EMP and pooled effects.
- tests/: Node built-in tests. fixtures.ts isolates old unit scenarios from randomized world generation.

## Important decisions
- World metadata is generated once from a string seed. Belts/clusters use global coordinates and continuous seeded value noise. Chunks independently sample the same field with per-chunk RNG, stable asteroid IDs and world-seeded shape IDs; visiting order does not change terrain.
- Chunk size is 1200 units; a 5×5 neighborhood is active. Leaving a chunk unloads unchanged objects; modified rocks are stored sparsely and destruction leaves permanent tombstones. No random asteroid replenishment resets mined ore.
- Save version 1 includes the generator version/spec, seed, world deltas, ship/modules, bases, exploration, inventory, pickups, projectiles, enemies/squads and RNG/timers. Runtime effects/sounds are transient. Base-building structures are not implemented yet; existing outposts are saved.
- Asteroid angles stay ordered and radii stay positive, preventing polygon self-intersections. Mining dents neighboring radii around the impact direction, then reduces area toward remaining material. Geometry changes only when whole units of material are removed.
- Ore health is fractional mining progress; amount is remaining finite yield. Ordinary mining releases all removed units; gunfire records unrecovered waste. Destruction only releases amount, then removes the asteroid. Pickups merge locally to control entity counts.
- Ships use polygon narrow-phase against carved ore; asteroid-pair contacts use updated conservative bounds. Per-block projectile hits can damage integrity and detach disconnected branches. Core-centered circle contacts remain an approximation for physical ship hulls.
- Performance: background baked into a repeating texture; asteroid textures rasterized only on first visibility/revision changes, bounded to 128 cached textures; visible sprite pool reused. Distant sleeping rocks skip contact simulation; local contacts use spatial buckets. HUD refreshes at 10 Hz, minimap/map at 5 Hz. No shaders or graphics dependencies.
- Earlier headless comparison improved from ~10 FPS to ~50–60 FPS after caching; benchmark values are environment-specific, not a universal hardware guarantee.
- Audio is gesture-unlocked, short synthesized cues with a master mute. M is map, N is mute. Presentation remains replaceable without changing model rules.
- Phaser's production bundle causes Vite's size warning (~350 KB gzip); accepted for the local prototype.

## Current interface/effects decisions
- Module definitions have no quantity limits and the editor is a panning viewport rather than a placement bounding box. Old 8/16/24 slot caps are superseded by the latest request. Core/item tiers remain progression prerequisites.
- Cached aggregate ship stats make power/thermal checks O(1) per operation. Per-module cooldowns, tractor target IDs and boost timers are independent. Mass affects movement and physical contact response.
- A module's operating power/heat is per second for continuous tools, per volley for weapons; volley consumption covers all flak pellets. Reactors generate energy, cooling dissipates heat, and weapons/miners/tractors/shield recharge/boosters refuse unavailable operations.
- Particle objects are preallocated once, reused and capped at 320. Offscreen effects are culled; important nearby events can replace lower-priority particles. Effects have their own deterministic visual RNG and do not alter model RNG or resources. Legacy mining fragment runtime was consolidated into the pool.
- Gameplay EMP pulses and projectile collision/damage are separate from their visual particles. VFX-disabled simulations are checked against identical effect-enabled game states.
- Default renderer is Phaser Canvas: a 33-module/eight-enemy/multi-beam combat fixture measured ~60 FPS versus ~35 using software WebGL. The background uses a viewport-sized repeating tile, avoiding a world-sized canvas. Optional `?renderer=webgl` is available for diagnosis.
- Cached ship sprites replace per-frame module vector drawing. Asteroid canvas textures are refreshed in place only when geometry revisions change; their shapes are not scaled as a substitute for deformation.
- Save v1 accepts optional energy/heat/EMP state and per-module target/burst fields; older v1 files receive safe power defaults. Overflow from older unlimited inventories is preserved as drops.

## Deployment
- GitHub Pages publishes the Vite dist artifact from main after npm ci/test/build. PRs only validate. Relative Vite asset URLs support the /VOIDFORGE/ project path.
- Browser saves belong to their site origin. Export/import moves a localhost save to the hosted page. The repository never contains player saves or credentials.

Editor dragging lives in `src/moduleDrag.ts`, uses pointer events with a movement threshold, and delegates validation/actions to the model. `moveError` shares side-effect-free validation between preview and committed movement. Builder DOM refresh pauses during active dragging to preserve the source and destination.

World expansion keeps the original 16-column asteroid ID namespace inside the former 19,200-square region; outer chunks use an offset namespace with fixed stride 4096. Optional generationSize/expansion fields migrate old v1 specs without moving original geography. Additional outer-field influence fades in over 2,000 units past the old boundary. The active 5×5 chunk window is independent of world area.

Module art remains centralized in drawModule: primitive beveled housings and equipment-specific hardware are baked into the existing texture cache and shared with editor icons/salvage. Tier bars are presentation only; module coordinates, collision and equipment definitions remain independent.

GameAudio routes the supplied MP3 media element and procedural effects through separate music/effects gain buses, then master gain/limiter. Vite bundles the local track using an import.meta.url asset reference. GameSettings owns the native paused modal and local preferences; particle density changes only the cosmetic pool RNG, never the simulation.

Weapon-to-ore impulse is applied in shootOre before deformation, using ORE_COMBAT tuning and existing asteroid velocity fields. Direct hits supply projectile direction; area hits supply outward blast direction. Existing contact resolution handles enemy damage and kill rewards without another physics system.

Five-tier progression extends the existing definitions without changing tiers 1–3. data.ts owns normal stats/durability/costs; abilityConfig.ts owns special names, descriptions and tuning; abilities.ts exposes shared onFire/onHit/onMiningHit/onDamageTaken/onBoost/onEnergyDeficit/onOverheat hooks and timer utilities. GameModel applies returned plans through normal damage, power and finite-ore paths. Side effects use bounded presentation events; arcs and fields are rendered independently.
Optional per-module AbilityState, coreAbility, novaFields and special projectile flags persist in v1 saves; older saves default safely. Piercing uses per-projectile hit IDs with a bounded swept-hit loop. EMP secondaries share the pulse hit set and cannot cascade. Reflection applies direct enemy damage. Nova overlaps take maximum rather than summed damage. Global special limits are 24 guided missiles, 96 one-generation fragments and 8 nova fields; normal installation quantities remain unlimited.

Regional populations: populationConfig.ts centralizes timing, threat targets, placement safety and active-area budgets. world.ts retains original seeded generation (arrival salts affect only replacement candidates), stores depleted field slots plus one current generation each, and uses a separate negative numeric ID namespace for replacements. Capture/snapshot preserve replacement geometry/momentum; original IDs remain tombstones. Active-region lookup is bounded to the 5×5 chunk neighborhood.
EnemyPopulation stores per-region reinforcement deadlines/counters, dormant Enemy records and patrol anchors. GameModel schedules population work every five game seconds, passes camera/ship blockers and supplies unique actor IDs; existing AI/contact/projectile paths remain in charge of combat. Defeat recording guards reward duplication. Optional world.population and GameSave.population fields migrate v1 saves; deadlines use saved elapsed game time, so unloaded catch-up needs no distant object creation or wall-clock awards. Sleeping actors count against geographic targets. Boss cooldown/reward hooks are implemented as a ledger only because no boss actor system currently exists.

Denser worlds extend WorldSpec with optional persisted populationFields geography. Original generateChunk sampling explicitly excludes this layer, preserving old IDs/RNG/geometry. Supplemental templates append in a 200,000,000-offset namespace with at most 32 candidates per chunk; activate defers them to the population scheduler rather than spawning into view. Source-slot ordering stays stable, baseline chunks are cached during scheduling, and active region targets expand to include the new layer.
Outfitter DOM refreshes snapshot and restore per-panel/outer scroll offsets. Weapon pushes cap added motion without braking pre-existing faster collision momentum. Starter weapon balance is data-only; later-tier stats remain unchanged.

Moving belts: random.ts contains the existing RNG/hash helpers, re-exported by world.ts. beltMotion.ts owns seeded motion definitions, reversible parent transforms, per-rock bounded variation/spin, analytical velocity and sparse physical offsets. Definitions and motionEpoch live in WorldSpec; optional Asteroid.motion/rotation/drift fields retain v1 compatibility. Old worlds choose their saved game time as the new epoch, keeping initial poses stable.
Chunk activation runs on source-cell changes or every two game seconds. It inversely maps the player through nearby motion groups, queries cached reference chunks, projects candidates into current space, filters/deduplicates and prioritizes nearby entities under the local budget. A sparse modified-rock index preserves mined/pushed objects independently of source chunks. Unmodified belt members reconstruct from time; unloaded bodies do not receive per-frame physics.
Mining helpers convert world/local points with current rotation. Collisions, projectile sweeps and LOS share those coordinates; cached sprite rotation changes independently of polygon revisions. Regeneration slots retain parent motion IDs and validate current-space candidates. Drops carry optional velocity with 50% inheritance. Local enemy steering uses moving-rock lookahead; current rich moving groups influence regional threat without new enemy archetypes. Cosmetic dust stays in the bounded EffectPool.

Motion definition lookups and per-rock variation parameters are cached. Source templates are culled at analytical current positions before cloning, and active source-chunk references survive cache refreshes so multi-belt streaming does not thrash the bounded background cache.

Pixel-art pass: `src/sprites.ts` paints baked sprites with the plain Canvas 2D API and has no Phaser dependency. World sprites (asteroids, enemy hulls, modules, stations) use one pixel per world unit; the backdrop is coarser. Sprites are enlarged with per-texture nearest-neighbour filtering (global antialias stays on so text is smooth). Each sprite is drawn small, then `snap` forces hard alpha, maps every texel to a small per-sprite palette and adds a one-texel dark outline, so there is no anti-aliasing or gradient. One world-fixed light from the upper left shades non-rotating sprites (asteroids, stations); rotating sprites (enemy hulls, modules) are shaded symmetrically about their axis. Asteroids are painted per pixel as cobbled rock: a jittered-grid cellular pattern (fixed per asteroid id) gives rounded stone plates with dark crevices, and ore-coloured glowing pockets fill a branching central cavity, with more pockets exposed as the rock is mined. The silhouette is the collision polygon and sprites are re-rasterized only on a geometry revision. The background is three viewport-sized parallax tile layers (posterized gas clouds x4 at 0.1, far stars x2 at 0.28, near stars x2 at 0.55) seeded from the world seed, with integer tile offsets. Stations are drawn pixel by pixel as a ring station (octagonal core, landing deck, truss spokes, habitat ring, solar wings, dish, fuel tanks) inside the 220-unit safe ring; base labels sit above it. The four enemy hulls are gunmetal part-based designs (mirrored plates, guns, engines, seams) with a muted faction accent, baked at their true size. Modules stay centralized in `drawModule` and are baked at one texel per unit (16x16) with `crispModule`. Particles blend additively. Sprite painting uses its own seeded RNG and never touches simulation state.

Enemy classes are data-driven in `ENEMIES` (data.ts): each has threat, hull, shield/regen/delay, speed, acceleration, mass, detection/range/preferred distance, a behaviour tag (hold, flank, kite, reload, carrier, guard), a weapon list and a loot table. Internal keys raider/scout/tank/sniper are kept for save compatibility (labels: Pirate Raider, Pirate Interceptor, Heavy Gunship, Railgun Sniper); frigate, carrier, defender and drone are new. `EnemyWeapon` supports multi-shot (count/spread/offset), limited-turn homing, a telegraphed charge that locks its aim `ENEMY_AI.chargeLock` seconds before firing, and target leading. All enemy damage goes through `damageEnemy` (shield first, then hull); all enemy fire goes through `enemyShot`, which tags bullets with their weapon type so existing weapon sounds and projectile art apply. Alerted movement is one steering step: radial (close/hold/back off) plus behaviour strafe, plus separation from other enemies and repulsion from nearby asteroids, limited by acceleration. Carriers spawn `drone` enemies up to `drones.max`; drones do not count toward the spawn cap. Defenders remember a home point and ignore the player beyond `leash`. Enemy shots survive `ENEMY_AI.shotMargin` beyond the view so long-range fire reaches the player.

Enemy AI is a lightweight state machine. `nextEnemyState` in `src/enemyAI.ts` is a pure priority function over an `EnemySituation` (visible, remembers, inRange, leashed, awayFromPost, guard, strafes, reloading, retreating, repositioning) returning patrol, investigate, chase, attack, strafe, retreat, reposition, defend or return; the model stores it on `enemy.state` and maps each state to a radial/strafe steering intent. Memory: seeing the player (or a squad mate seeing them, or being hit) records `lastSeen` for `ENEMY_AI.memory` seconds; without sight the enemy investigates that point at reduced pace and holds fire, then gives up. Retreat triggers once per enemy when hull drops below the class `retreatAt` fraction and lasts `retreatTime`. Reposition covers reload back-off and a timed sidestep triggered when actual movement stays under 30% of intended speed for `stuckTime`. Asteroid avoidance adds a tangential slide toward the side nearer the goal so enemies route around rocks. Patrol and return reuse the existing squad-formation and lone-wander code (guards head for their home point). Strafing classes reverse direction every `strafeFlip` seconds. The flight view shows a pip beside each health bar: amber investigating, red fighting, white retreating.

Danger regions: `dangerAt(spec, x, y)` in `src/world.ts` returns level 1-4 purely from the saved world spec, so it is deterministic per seed, needs no new save data and works for old saves. Every cluster and belt (including expansion geography beyond the legacy edge) gets a level from `DANGER.ore`, +1 when its density exceeds `richDensity`, plus a seeded -1/0/+1 variation; the level applies inside `core` of the field's radius/width and one less out to `fringe`. A point takes the highest level of the fields covering it; open space is level 1. Within `safeRadius` of the first base the level is always 1 and within `calmRadius` it is capped at 2. `ENEMY_SPAWN.solo/squads` are indexed by level, and spawns use the level at the spawn point, so richer fields draw stronger classes. The HUD chip shows the level at the player, a message announces crossing into higher danger, and the sector map tints explored cells by level (cached per seed in `src/map.ts`). In `main.ts`, repainting the backdrop on world switch must call `setTexture` with the tile key: a TileSprite's own `texture` is its internal canvas.

Bosses reuse the enemy pipeline. A boss is an `ENEMIES` entry with a `boss` block (`BossDefinition`: phase threshold, phase-two weapon set, one reinforcement call, escorts, mounted parts); its turrets and shield generators are ordinary enemies flagged `part`, linked by `parent` and a ship-space `mount` offset, repositioned on the hull every tick, firing through the shared `enemyFire` method and removed silently (no kill, no loot) when the boss dies. Boss shields recharge only while a `shieldSource` part survives. Large hulls turn at `turnRate` rather than snapping; bosses ignore EMP stun and separation. `bossSites(spec)` in `src/world.ts` picks each boss's cluster from the saved spec (preferred ores, then richness, at least `BOSS.minHomeDistance` from the start and clear of every base), so sites need no save data. The model wakes a boss when the player is within `BOSS.wake`, overrides danger to extreme inside a living boss's territory and caps it at medium once defeated, and stores `defeatedBosses` in the save (optional field; old saves load with none). The DOM boss bar in `main.ts` shows hull with the phase marker, shield, surviving turrets and generators; the sector map marks explored boss territories. All three bosses use it. Optional `BossDefinition` mechanics: `finalAt`/`finalWeapons` add a third phase; `phaseSpeed` speeds movement from phase two; `surge` makes the boss hold fire and recharge shields on a timer while a shield source lives; `emp` is a timed area pulse with a `charge`-second warning ring that damages and drains energy inside `radius`. A part with `weakPoint` never takes damage itself: once its boss is in phase two, hits pass `weakPoint` times the damage to the boss hull past its shield (`damageEnemy` destroys the boss directly if that kills it; `enemy.gone` guards against double destruction). Drone launching uses its own `cooldown3` timer so armed ships can also carry drones, and counts only `drone` children. Crystal Leviathan: charged rail beam, plasma fans, drones, shield surges fed by two crystal nodes. Reactor Titan: twin plasma, guided barrages, EMP pulse, three phases, two reactor vents exposed from phase two.

Sound cues: the simulation emits sound-only `EffectEvent`s of type `cue` through `GameModel.cue(name, at, size)`. They bypass view culling (so off-screen snipers and missiles are heard), carry a `volume` that fades to zero at `HEARING.range` from the player and a `pitch` derived from the source's radius (larger hulls sound deeper), and are skipped by the particle pool. Hostile weapon fire sends its sound as a cue and marks its muzzle flash `silent` so it is not played twice. `SOUND_PROFILES` in `src/audio.ts` defines every cue as one oscillator sweep with optional filtered noise burst (`noise`/`noiseTone`), tone repeats (`repeat`/`every`) and a per-cue minimum interval (`gap`); `GameAudio.play(cue, pitch, volume)` keeps the 14-voice cap. Cue names are typed as `SoundCue`, so the model cannot emit a cue without a profile. New cues: railCharge, lock, drone, alert, bossWarning, bossPhase, bossDown, surge, empCharge, moduleLost, hull, death. As before, sound never feeds back into simulation state or RNG.

Merge with main's renewable populations (2026-11-13): main's `EnemyPopulation` is the only spawner; the branch's old `addEnemy`/`addPatrolGroup` timer is gone. `ENEMY_SPAWN` is now `{ normal, elite }` pools per danger level, `regionDanger` (median of five `dangerAt` samples, home region forced to 1) selects the pool for a population region, and `isElite` derives the elite class from those pools. Population-spawned enemies get shields and guard posts lazily in the AI loop. `spawnEnemy` marks its enemies `populationExempt`, which `EnemyPopulation.update` passes through untouched. Main's `hitEnemy` calls `damageEnemy`, so level-5 abilities respect enemy shields and weak points; `enemy.rewarded` (main) replaces the branch's `gone` flag as the single destroy guard. Boss defeats call `recordBossDefeat`; `defeatedBosses` is a getter over the ledger (`bossReady`), so bosses return after `POPULATION.bossInterval` and their territory is extreme again, with repeat kills paying `HORDE.repeatBossLoot` of the loot. Sprite baking covers all five module levels. Asteroid sprites rotate with main's `a.rotation`; the baked upper-left light therefore turns with a rotating rock, which is accepted to keep textures cached.

Horde events: `GameModel.horde` holds `{ timer, warning, angle, total }` and is saved as an optional field. `updateHorde` runs each tick after danger is known: the timer only counts down outside `DANGER.safeRadius` of the first base and while not docked, using `HORDE.interval[danger-1]`; at zero it starts a `HORDE.warning`-second alert with a random approach angle and repeats the `hordeAlarm` cue. Docking during the alert cancels it and sets the timer to `HORDE.retry`. When the alert ends `spawnHorde` places `HORDE.size[danger-1]` enemies in an arc at `HORDE.distance`, mixing `ENEMY_SPAWN.normal` and `elite` pools by `eliteShare`; they are `populationExempt`, flagged `horde`, never retreat, take no guard post and have their `lastSeen` refreshed every tick so they converge through the normal state machine. Horde members beyond `HORDE.despawn` are removed without kills or loot. When the last one dies in combat the model drops `HORDE.reward` times the danger level near the player. `main.ts` toggles `horde-alert`/`horde-warning` classes on `body` (stepped red flash on all HUD panels and the screen edge, with a reduced-motion fallback), shows the `#horde-banner`, and draws chevrons toward the approach angle.

## Fleet / encounter extension (2026-11-13)
- `enemyDefinitions.ts` extends the existing `ENEMIES` registry with factories, specialized archetypes and boss component layouts. Legacy keys and encounters are preserved. `fleetConfig.ts` owns faction colors/compositions and bounded scaling.
- Regional population selects factions from seed + region, then uses existing squads, spawn validation, sleep records and budgets. New actor armor/maxHealth/damage/accuracy/reward fields are optional saved values; absent armor preserves legacy actor damage behavior.
- Existing model damage/fire/death paths remain authoritative. Components gate weapons/drone bays/mining; engines reduce movement and coils gate hazards. Enemy industry calls the same finite mining primitive and transfers actual drop amounts into saved actor cargo.
- EMP interruption/immunity are optional v1 save fields; movement bypasses paid-system suppression. Boss ledger stores `requiresExit` independently of its cooldown/unique-reward flags.
- Hostile projectiles reuse a private bounded object pool after expiry, with optional homing/splash state reset. Pool and brief beam/hazard graphics are transient; enemy charge/cargo/phase/meltdown state is persisted. Cached sprites remain separate from gameplay.

Outpost construction (phases 1-3 of the outpost brief). `builder` is a normal ship module (`MODULES.builder`, five levels, level-5 Industrial Fabricator) gated by `OUTPOST.coreLevel` in `buildError`. Outposts are pure data in `src/outposts.ts`: an `Outpost` is a core cell plus a list of `Structure` blocks on the world construction grid (`OUTPOST.cell`, equal to the ship tile, aligned to world 0,0 so cell = floor(world / cell)). Block types and costs are `STRUCTURES` in `src/data.ts` (Outpost Core, wall, reinforced wall so far). The model owns `outposts` (saved as an optional field): `placeError`/`placeStructure` validate range, overlap, asteroids, ships, stations, core spacing, connection to an existing block within `OUTPOST.radius` of the core, and carried-cargo cost (after the Build module discount), then spend cargo and ship energy. `updateOutposts` advances construction (Build module speed while the ship is near, `OUTPOST.awaySpeed` otherwise) and runs the fabricator repair from carried iron and energy. `damageStructure` removes destroyed blocks, then anything no longer connected to the core; losing the core ends the outpost. Finished blocks stop and are damaged by hostile projectiles (`structureOnSegment`); the player's shots and all ships pass over them for now. Outposts are added to the population spawn blockers so asteroids and enemies never arrive inside one. Rendering: `paintOutpost` bakes each outpost into one canvas whenever `outpost.revision` changes (neighbour masks give brass frames on open sides, riveted seams and copper pipe runs on joined sides, scaffolding while under construction, cracks by wear level); only progress bars and the core glow are drawn per frame. `main.ts` draws the always-on large world grid and the fine construction grid (fades in over `OUTPOST.gridZoom`, forced on in Build Mode, thinned at far zoom) into a dedicated Graphics object with world-aligned line positions, and runs Build Mode (toggle key/button, catalog panel, snapped green/red preview, hold-to-drag placement, rotate, right-click/Esc exit) while suppressing weapon fire and mining input.

Outpost phase 4 (turrets, power, storage). `StructureDefinition` gained optional `generation`, `energyCapacity`, `storage` and `turret` (a `TurretDefinition`: weapon type, damage, cooldown, range, projectile speed/lifetime, energy per shot, turn rate, optional splash and guidance). `outpostStats` in `src/outposts.ts` totals these over finished blocks and is cached per outpost revision. Each outpost has a battery (`energy`) charged by generation and capped by capacity, and a mineral store (`stored`) capped by storage capacity; both are optional saved fields that default on load. Turrets (`updateTurrets`) run only for outposts within `OUTPOST.activeRange` of the ship: they look for the nearest hostile every `turretScan` seconds, turn at their own rate, and when aligned and off cooldown spend battery energy to push an ordinary player-side projectile into the shared `bullets` list (flagged `turret` so it survives off screen; missiles reuse the existing `guided` and `splash` handling). With too little energy the shot is skipped and `outpost.shortage` is set. `depositToOutpost`/`withdrawFromOutpost` move whole units between ship cargo and outpost storage within `transferRange` of a finished core, limited by the receiving capacity. When storage is lost, `spillOutpostOverflow` turns what no longer fits into pickups; a destroyed outpost spills everything. Rendering adds baked mounts for turrets plus pooled rotating head sprites, a reactor and storage block, and a DOM readout for the nearest outpost (power, peak turret draw, battery, storage, transfer buttons).

Outpost phase 5 (mining drones, docking). `Drone` records live in `outpost.drones` (saved): hangar block id, position, state (`idle`, `outbound`, `mining`, `returning`), target asteroid id, a single-ore `load` and a timer. `updateDrones` runs with the turrets, only for outposts within `OUTPOST.activeRange`. It keeps each finished hangar's roster at `STRUCTURES[kind].drones`, launches idle drones when the battery covers `DRONES.launchEnergy` and storage has room, and picks the nearest asteroid within `DRONES.range` that fewer than `perAsteroid` drones are already working. Mining calls the same `miningImpact` + `mineMaterial` the ship uses, so ore only ever moves rock -> drone -> outpost storage and rocks deform and deplete normally (`destroyAsteroid` when empty). A drone heads home when full, when its rock is gone or drifts beyond `range * leash`, or when the rock's ore differs from what it carries; with storage full it waits at the hangar holding its load. `dropOrphanDrones` releases the load of drones whose hangar is destroyed as pickups. `dockAt()` finds a finished block with a `dock` radius near the ship; pressing E away from a station calls `dockAtOutpost`, which deposits cargo and then repairs the ship for the normal `repairCost`, paid from carried cargo first and outpost storage second, or not at all if they do not cover it. Cargo transfer buttons also work at a docking station. Drones are pooled sprites with a thin beam while cutting.

Outpost phases 6-8. All sixteen block types from the brief exist in `STRUCTURES`. Blocks have levels 1-5: `STRUCTURE_LEVELS` holds the per-level multipliers (hull, output, turret damage, drone count) and `maxHealth`, `turretOf`, `dronesOf` and `outputOf` in `src/outposts.ts` apply them; `outpostStats` totals everything at level and exposes the level-5 flags. Level-5 specials are named in `STRUCTURE_ABILITIES` with their numbers in `STRUCTURE_SPECIAL`. `upgradeStructure` charges the build cost times the current level (Build module discount, plus the level-5 Upgrade station discount), from carried cargo first and outpost storage second, and needs an Upgrade station above `OUTPOST.stationLevel`; `repairStructure` charges iron per missing hull point. Both need a working Build module in range. Shield generators give the outpost a shield pool that absorbs damage to blocks within their radius, recharging from the battery after `shieldDelay`; hostile bullets carry `attackerId` so a level-5 generator can reflect. Turret fire adds heat, cores and cooling units remove it, and an overheated outpost holds fire until it is under 60% (a level-5 cooler purges instead). Repair stations mend the most damaged block in their radius for stored iron and battery energy; automatic repairs and the ship's fabricator both require iron to cover the rounded-up debt, so there is no free repair. Radar adds turret range and raid warning. Drones are serviced every few trips, faster with a Drone repair bay. Raids: each outpost has a `raidTimer`; when it elapses for an outpost worth more than `raid.minValue`, a raid party (`raidParty`, population-exempt) spawns on the far side from the ship, after a radar warning if there is radar. `raidOutpost` in the enemy loop makes any enemy with no fight against the ship attack a raided or nearby outpost, turrets and power first; hurt raiders retreat and are removed without kills or loot. Away from the ship (beyond `activeRange`) nothing is simulated: the outpost banks seconds in `away` (capped at `awayCap`) and raids as `pendingRaids`. When the ship is back within `resolveRange` for `resolveDelay` seconds (so the streamed asteroid field is loaded), `resolveAway` applies banked raids against a defence score from turrets and shields, then repair-station work limited by stored iron, then drone work, which is removed from the real asteroids in range with `mineMaterial` and credited to storage, so away mining can never exceed what exists or what storage holds. In Build Mode, clicking a built block selects it and the panel shows its level, stats, level-5 special and Upgrade/Repair buttons with prices. Small live overlays (core gear teeth, cooling fan, radar sweep, shield outline) are drawn per frame; everything else stays baked.

## Navigation HUD and fleet
`src/nav.ts` is pure Canvas 2D drawing plus bearing maths: `navMarkers` lists the things worth steering to (discovered bases, outposts, known undefeated boss sites, an incoming horde, player waypoints), `drawRadar` paints the north-up minimap and `drawCompass` the heading strip. Both draw into DOM canvases created in `main.ts` (`#nav-radar`, `#compass`), not Phaser objects, so they scale with the HUD; the compass backing canvas follows its laid-out width at 2x. `mapToWorld` in `src/map.ts` is the inverse of the sector-map transform and turns a map click into a world point for `GameModel.toggleWaypoint`. Limits and colours are `WAYPOINTS` in `src/data.ts`.

The fleet is model state: `shipName`, `hangar: StoredShip[]` (id, name, core level, modules, hull) and the usual `coreLevel`/`modules`/`player.health` for the ship being flown. `buyShip` spends stored minerals (`FLEET.cost`, scaled by `FLEET.growth` per ship owned) and parks a starter hull. `switchShip` works only at an active station: it moves carried cargo to storage (so a smaller hold never drops ore), swaps the hull fields and resets transient ship state (ability, links, shield, energy, heat). Stored minerals, discoveries and outposts belong to the pilot, not the hull. Hull paint is an index into `FLEET.paints` (`shipPaint` for the flown ship, `paint` on each `StoredShip`); `paintIndex` turns unknown saved values into bare metal. `paintHull` in `src/sprites.ts` recolours only the neutral hull metal of a baked module icon, and `shipTexture` in `main.ts` bakes each painted variant once on first use, so paint costs nothing per frame. `shipName`, `shipPaint`, `hangar` and `waypoints` are optional save fields. Wide-screen scaling is CSS `zoom` on the HUD panels in `src/style.css`.

## Save storage
`src/persistence.ts` writes each save to two stores. `localStorage` (key `voidforge.save.v1`, timestamp in `voidforge.save.at`) is synchronous, so a save issued while the tab closes lands, but it holds only about 5 MB. IndexedDB (database `voidforge`, store `saves`, records `current` and `backup` of shape `{ at, text }`) is asynchronous and large. `saveGame` returns an error immediately only when neither store exists; if the small store rejects the write and the large one later fails too, the `onError` callback reports it. `loadSavedGame` is asynchronous, takes the newer copy by timestamp (saves from before this change count as time 0) and falls back to the other copy if the newer one does not parse, so `main.ts` reads storage before creating the Phaser game. `saveText` is the single serializer for saves and exports; it rounds non-integer numbers to four decimals and leaves integers (ids, seeds, RNG state) exact. Both stores are passed in as plain objects, which is how the tests exercise quota failures without a browser.
